# How many backends completed a real install -> list -> binary -> remove round-trip, per
# host class. A ratchet: it may rise, and a run that falls below the recorded number fails.
#
# WHY THIS EXISTS (G-11, owner ruling 2026-07-28 — Q12). The coverage audit asks "did every
# registered backend get a lifecycle OR a plan-smoke", and a plan-smoke satisfies it. So a run
# with 4 real lifecycles and a run with 15 both PASS. The clean Windows sweep reported 4 — not
# because anything broke, but because 8 of 15 canaries were already installed on that host and
# the harness correctly refuses to remove software the user already had. **The gate's coverage
# is therefore inversely proportional to how much the machine is used, and it never noticed.**
#
# A fixed threshold was rejected: the honest number varies by host, and a number guessed once
# is the kind of constant this repo keeps discovering was wrong. A ratchet needs no guess. It
# only ever asserts "this host class did better than this before, so it can again".
#
# HOST CLASS is `<harness>-<os>-<ci|local>`. `ci` and `local` are separate on purpose: that IS
# the difference the finding is about — a clean runner installs the canaries, a developer's box
# already has half of them. Holding a developer to CI's number would make the gate red on every
# machine that has ever been used, which is how a gate learns to be ignored.
#
# For a container, `<os>` is the IMAGE (`SHALL_IT_IMAGE`, declared by each Dockerfile), not the
# distro underneath it. `/etc/os-release` says `ubuntu` for both the ubuntu image and the `tools`
# image, because `tools` is built on Ubuntu — so the two runs that differ most in coverage (7 and
# 25) were filed under one record, and whichever wrote it last made the other permanently wrong.
#
# A container is also always `local`: `docker run` passes no `CI`, and that is left alone rather
# than "fixed", because the ci/local split exists for how used a machine is and a disposable
# image is equally clean either way. One number per image is the honest granularity there.
#
# TO RAISE ONE: run the sweep, read the number it prints, edit the line, commit it. The harness
# prints the exact edit when a run exceeds the record. Never lower a line to get green — that is
# the one edit this file exists to make visible in a diff.
#
# THE FIRST EXCUSE IS DATED, and lives here too:
#
#     drift <host-class> <backend> <YYYY-MM-DD>   # and what broke, in the tool's own words
#
# It expires after fourteen days (`DRIFT_WINDOW_DAYS`, in both harnesses). A backend with no line
# — or with an expired one — is NOT counted toward the floor, so the shortfall is reported rather
# than absorbed, and the run prints the line to add with today's date on it.
#
# **Why an excuse needs a date at all.** The case it was built for clears by itself: a GitHub
# rate-limit window has twenty minutes left on it and the next nightly measures the backend
# again. The case that turned up on 2026-08-21 does not. Hackage rotated its TUF root past the
# trust anchors compiled into the cabal-install Ubuntu ships, so every `cabal` install in the
# `tools` image failed, and no later run would have cleared it — only an image change would.
# Excused and never aged, that is `|| true` with better manners: the coverage leaves, the log
# says so at full volume, and every run stays green. Fourteen days is long enough to land the
# repair and short enough that nobody forgets it; the expiry is a FAIL naming the backend and
# how long it has been excused, not a note.
#
# In THIS file and not one of its own, deliberately. `scripts/` is excluded from the Docker build
# context, so a gate that lives there reaches a container only by being mounted — and a gate that
# is not mounted is a gate not in force, which this repository has already paid for once, with
# the ratchet absent from five legs and every one of them green. This file is mounted at all five
# call sites already.
#
# **What this costs, stated rather than discovered.** Before the register, an `Exhausted` install
# was excused automatically, so a GitHub rate-limit window stayed green with nobody touching
# anything — which is what R-3 was for, after two red jobs over a classification the program had
# already made. Now an unrecorded one does not count, so a genuine one-off flake turns a nightly
# red once. That is the trade, and it is accepted in this direction because the two cases recover
# differently: a real transient is measured again on the next run and goes green with no action at
# all, while real drift stays red every night until somebody either repairs it or writes the line.
# Red once and self-healing, against green for ever and silently uncovered.
#
# EMPTY ON PURPOSE, below. A `drift` line is a debt, and this is the file that makes one visible
# in a diff. The 2026-08-21 cabal rotation needs no line: the `tools` image now seeds Hackage's
# current root before `cabal update`, so the lifecycle is measured rather than excused.
#
# TWO THINGS ARE EXCUSED, and neither lowers a line. A backend whose install failed for a reason
# Shall classed as passing and did not clear on a retry — a rate-limit window, a held lock — is
# counted toward the floor and named in the run, PROVIDED an unexpired `drift` line below says
# it may be. So is a backend whose KERNEL MODULE this host does not have: a container borrows the host's
# kernel, so btrfs, device-mapper and the out-of-tree ZFS module are facts about the machine, and
# no retry here ever measures them. The two are recorded apart because their remedies differ, and
# a run that uses either says which. Before that second excuse existed, a correct run on a kernel
# without ZFS measured 7 against this file's 8 and reported a collapse that had not happened.
#
# A host class with no line here is not failed — a gate that fails the first time it sees a new
# platform is a gate that stops people adding platforms — but it is not PASSED either. It prints
# the line to add and counts as neither, because a record that is not there compares nothing.
# That branch was a counted PASS until 2026-07-30, and every class below was taking it: the whole
# matrix reported the ratchet green while one developer's machine was the only place it ran.
#
# Every number below was read from CI run 30503630610 (2026-07-30) except the first, which
# predates it. `gentoo` is absent on purpose: it runs SMOKE_ONLY, installs nothing, and its
# honest count is 0 — a floor no run could fall below.
