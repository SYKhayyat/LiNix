# Which rows the terminator probe has MEASURED on each host class. A ratchet over names: the
# set may grow, and a run that fails to measure a name recorded for its class fails.
#
# WHY THIS EXISTS. `tests/terminator_probe_tests.rs` reports what it measured and asserts only
# that nothing it measured contradicts `src/core/argv.rs`. Both halves of that are satisfied by a
# run that measures nothing, and one already happened: the arch image began running its harness
# as an unprivileged user so `yay` and `paru` could be driven at all, and on that user `pacman` —
# whose row reads `Evidence::Measured` on the strength of this very leg — stopped answering. Six
# binaries still did, so the probe reported six, printed `inconclusive: pacman`, and passed. The
# row went on claiming somebody had run it while the only leg that ever ran it had quietly
# stopped.
#
# A count would not have caught it either. Seven rows measured is not the claim; measuring THESE
# seven is, and a set that swaps one name for another keeps any count identical. So this file
# records names.
#
# HOST CLASS. `container-<image>` from `SHALL_IT_IMAGE`, which every integration Dockerfile
# declares and which survives `--entrypoint sh`; otherwise `<os>-<ci|local>`. The image name and
# not the distro underneath it, for the reason `lifecycle-floor.txt` gives at length: `tools` is
# built on Ubuntu and carries thirty managers the ubuntu image does not.
#
# A container needs no ci/local split — it is equally clean either way — and `<os>-local` is
# deliberately empty below. A developer's machine has whatever managers that developer installed,
# and holding every clone to one person's PATH is how a gate earns its way onto the ignore list.
#
# PRIVILEGE IS PART OF THE CLASS, and it is not in the name. This probe reads what a manager SAYS
# about an operand, and a manager that refuses before it parses one says nothing either way — so
# the same image measures seven rows as root and six as an ordinary user. CI passes `-u 0` to the
# probe step for exactly this reason. If a leg is ever switched away from root, these lines are
# what turns that into a named failure instead of a quieter report.
#
# TO ADD A NAME: run the probe, read the line it prints when it measures more than is recorded,
# paste it. Never delete a name to get green — a name that stops being measurable is the finding
# this file exists to produce, and the fix is to restore the measurement or to demote the row in
# `src/core/argv.rs` to the inference it has become.
#
# A host class with no line here is not failed and is not passed: it prints the line to add.
# Failing the first run on a new image is how a gate stops people adding images.

# Every line below was read off a run's own output, and the run is named. None was estimated.
#
# The arch line is the regression above, written down. Measured twice on 2026-08-15: locally,
# both privilege levels off ONE build of the suite — root measured these seven, `shall` measured
# six and lost `pacman` — and on CI run 31919417555, whose probe step passes `-u 0` and reported
# the same seven. The AUR helpers are the reason the harness runs unprivileged and `pacman` is
# the reason the probe does not.
container-arch cargo gem pacman paru pipx uv yay
# The rest of the fast matrix, from that same CI run.
container-ubuntu apt cargo gem pipx uv
container-fedora cargo dnf gem pip pipx uv
container-alpine apk cargo gem pipx uv

container-void cargo gem pipx pnpm uv xbps-install xbps-remove yarn

# Measured locally 2026-08-16, the probe step driven as `ci.yml` drives it, `-u 0`. `slackpkg` is
