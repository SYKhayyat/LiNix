# Handoff — 2026-08-12: the god object, and the shape it took when it left

Picks up from `docs/GRADE-2026-08-12.md` §5, finding 2: *"The god object is smaller and closed,
not dissolved. 137 call sites still take `&App`."*

## What was wrong

`App` was a **service** wearing a composition root's name: 12 public fields, 49 methods, and 139
call sites taking `&App`. No handler declared what it needed, so:

- none could be exercised without building the whole world — 48 backend registrations, a state
  file, a WAL, a snapshot-provider probe — to test a function that reads one boolean out of
  `Config`;
- nothing could see the coupling. `&App` type-checks everywhere, a field is never unused because
  something else uses it, and a method reaching eleven collaborators to use two is
  indistinguishable from one that needs eleven.

## What was done

### 1. `App` has no behaviour left

Every method that *decided* something moved onto a type that holds only what that decision reads.
`app/context.rs` went **1,201 → 401 lines**; `App` went **49 methods → 28**, all of them either
construction or a one-line factory.

| moved to | what went there |
|---|---|
| `app/inventory.rs` — `Inventory` | `list`, `get_info`, `search`, `warm_installed`, `installed_but_undeclared`, `owned_system_package_names`, the backend fan-out, `UndeclaredReport` |
| `app/declarations.rs` — `Declarations` | `declare`, `declares`, `retarget`, `undeclare`, the dry-run tense |
| `app/managers.rs` — `Managers` | `update`, `upgrade` |
| `app/vcs.rs` — `Vcs` | `git_manager`, `git_autocommit` |
| `app/sync/resolver.rs` — `StateResolver` | `resolve_spec`, `declared_backend`, `queried_resource`, `reject_unusable_line`, `host_facts`, `host_backends`, `vocabulary`, `require_known_backend`, `require_known_spec_backends` — nine methods that were pure forwarders to a resolver the caller could hold itself |
| `app/holds.rs` — `Holds::assemble` | the ledger + manifest union |
| `core/snapshot.rs` — `SnapshotManager::prune_by_policy` | retention, which `sync` and `snapshot prune` each derived themselves |

### 2. 139 `&App` call sites → 51, and the 51 are all dispatch

Every handler now takes what it reads: `&Config`, `&Arc<BackendRegistry>`,
`&StateResolver<'_>`, `&Inventory<'_>`, `&Declarations<'_>`, `&Vcs<'_>`, `&CommandExecutor`,
the state mutex. **Nothing under `src/app/`, `src/core/`, `src/backends/`, `src/config/` or
`src/model/` takes `&App` any more** — the remaining 51 are in `src/verbs/` and `main.rs`, which
turn one argv into one command and are entitled to the whole context.

### 3. The parameter list the god object turned into

`SyncEngine`, `ProfileManager` and `EphemeralShell` each took **the same eleven collaborators,
in three different orders** — 33 parameter declarations, 55 arguments across five call sites,
each `new` carrying `#[allow(clippy::too_many_arguments)]`. Passing twelve fields one at a time
is the same coupling with more places to get it wrong. They now take one `Machinery`
(`app/machinery.rs`), `App::machinery()` builds it, and the three factories are one line each.

`SyncEngine` lost its lifetime parameter in the process (`config: &'a Config` →
`Arc<Config>`), so `SyncEngine<'_>` is now `SyncEngine` and `App::sync_engine()` is no longer
async.

### 4. Two more synonyms deleted

- **`CommandExecutor::duplicate()`** was `self.clone()` and nothing else, and the tree used both
  spellings (55 sites). Deleted; what a clone actually shares — the execution layer, the dry-run
  filesystem, the per-manager lock map, the installed memo — is now a doc comment on the struct,
  which is what the second name was failing to say.
- **`MetricsCollector::record_operation`** took eight positionals, three of them adjacent
  unsigned integers (`retries`, `bytes_downloaded`, `batch_size`). It is one `Recorded` struct
  now — which is, minus two derived values, exactly the record it was reassembling.

### 5. A bug the split exposed

`App::vocabulary()` built a `Vocab` **without** `with_groups`, while `StateResolver` built one
with it. So a `groups` name (U18) expanded when `sync` parsed a file and was *"not a backend"*
when `install`, `uninstall`, `teleport` or `module` wrote the same line — one program, two
vocabularies, disagreeing about what a name means. U18's ruling says a group *"expands to exactly
that chain in the one parser"*; there were two. There is one now, and `shall install tools:rg`
resolves the way `shall sync` always did.

### 6. The rules are now checked

`tests/the_composition_root_is_not_a_service_tests.rs`, two tests, both self-tested against a
deliberate violation before being trusted:

- **`every_method_on_the_composition_root_is_a_factory`** — no method on `App` outside its
  constructors branches. A method that decides belongs on the facet it decides about.
- **`only_the_dispatch_layer_takes_the_whole_app`** — nothing outside `src/verbs/` and `main.rs`
  names `&App` in a parameter.

Neither is something `cargo`, clippy or the type system can see.

### 7. A latency gate that measured the test runner

`every_config_only_command_stays_inside_its_class_budget` went red on a full-suite run and
passed in isolation. Measured directly on the same binary: **111–131 ms against a 5-second
budget** — the box was busy, `shall vars` was not slow. One sample of a wall clock, taken while
five hundred other tests spawn processes, is a measurement of the suite.

All three wall-clock budgets in `tests/latency_budget_tests.rs` now take the **fastest of three
runs** (`run_timed_floor`, short-circuiting the moment one lands under a second). A regression of
the order of magnitude these budgets exist to catch is slower in *every* run, so the floor loses
nothing the test could see — and a gate that goes red for reasons nobody controls is a gate
people delete, which is what the file's own header already says about the number.

## What was NOT done, and why

- **`StateResolver` is now the largest type in the tree (38 methods, ~2,000 lines).** Three
  of those methods are mine. Its clusters — priority/vocabulary, variables, model resolution,
  single-line questions — share nearly all of its state (`locks`, `prefer_locks`,
  `vars_override`, `active_override`, `remote_gate`), so splitting it buys much less than
  splitting `App` did and costs a facet-per-cluster carrying the same eight fields. **It is the
  next honest target and it is not obviously worth it.** Measure before moving.
- **`CommandExecutor` has six responsibilities** (process running, filesystem, locking, sudo,
  command existence, the installed memo) across 35 methods. The filesystem half is 24 call
  sites and would extract cleanly into a `Files` facet — but the fs methods and the run methods
  share the dry-run `vfs` deliberately, so they are one abstraction ("effects on this machine,
  real or simulated") more than they are two. Left alone on purpose; say why if you change it.
- **The remaining 51 `&App` handlers** have a median of four collaborators and mostly forward to
  each other (`handle_rollback` → `handle_sync`, `handle_clean_cache` → `perform_maintenance`).
  Narrowing them further means narrowing the orchestrators, which is where `&App` is honest.
- **The dead-`pub fn` scan is clean.** 1,110 production `pub fn`; 39 have no *production* caller
  and every one of those is referenced by a test (the fake executor's API alone is 100+
  references). Nothing is referenced nowhere. `tests/a_pub_fn_nobody_calls_is_dead_tests.rs`
  already guards this.

## Verification

`cargo build --all-targets` · `cargo clippy --all-targets --all-features -D warnings` ·
`cargo fmt -- --check` · `cargo test --no-fail-fast` — all four green. 535 tests
(533 before, +2 for the new guard).

Net: **64 files, +1,461 / −1,800.**
