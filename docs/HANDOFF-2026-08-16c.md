## What this round finished

### `nixos:` — `J5`, ruled in four answers and built

`nix:` means `nix profile install` on every host including NixOS; `nixos:` means the system
configuration. Two prefixes because a NixOS user may want both and a shared config file must mean
the same thing on every machine. Shall renders `shall-packages.nix` whole from the model, inserts
one `imports` entry into `configuration.nix`, runs `nixos-rebuild switch` once per batch, and
restores **both** files if the rebuild fails. `[nixos] config_dir` and `manage_imports` in
`preferences.toml`. `shall export --format nix` renders through the same function.

### Before that: the published binary could not start on NixOS *or* Alpine

A `-gnu` binary needs a loader Alpine lacks and NixOS replaces with a stub that refuses. **Alpine
was in the integration matrix**, so a supported platform's binary could never have run — and both
installers reported success because neither ran what it downloaded. Fixed three ways: both
installers now execute `--version` and fall back to a source build,
`x86_64-unknown-linux-musl` joined the release matrix, and x86_64 Linux always takes it. One
static artifact, measured on ubuntu, alpine, `nixos/nix` and real NixOS.

### The four defects, which are the transferable part

Every hermetic layer passed a backend that did not work: 11 unit tests, a real Nix parser over
every generated module, clippy, fmt, and a Linux compile check.

| | defect | how it presented |
|---|---|---|
| 1 | `imports` appended *outside* the attribute set | `syntax error, unexpected '='` — breaks the boot config |
| 2 | `nixos-rebuild` ignored `config_dir` | 45.9s rebuild, exit 0, **`SUCCESS` with nothing installed** |
| 3 | root-owned `/etc/nixos` written via `std::fs` | `Permission denied (os error 13)` |
| 4 | rollback restored one of two changed files | **left the machine unbuildable** |

Defect 4 was introduced *while fixing* the first three, in the function whose own comment says it
exists to stop the files misdescribing the system.

**The lesson is not "test on real hardware".** It is that the parse gate existed and pointed at
the safe half: it validated the file Shall *generates* while every defect was in the file Shall
*edits* and the command Shall *runs*. It validates both now.

**And the bound was self-inflicted.** This work first recorded, in three documents, that no
container is NixOS so `nixos-rebuild` "is argv-checked and not executed… until a real host exists
that row is inference." A real host was one `wsl --install --from-file nixos.wsl` away. Writing a
limitation down confidently is what stops the search for a way around it.

### Docs: out of the changelog voice

The README had accumulated the spec's register — dated measurements and fix-history in prose a
user reads to learn what the tool does. The exit-code section gave four dates and *"until this it
returned 0 every time"* to someone asking what `3` means. Also: `nixos:` is now in the grammar's
prefix list (it was discoverable only from a coverage table), Locking is 86 → 75 lines,
`DEVELOPMENT.md` has the two out-of-chain gates, and `ARCHITECTURE.md` knows about a sixth shape
that cannot be a data row.

**One gate passed while its own invariant became false.**
`backend_count_matches_the_spec_tests` says *"a new backend cannot change one without the other"*
— `nixos` changed neither, because the same change that added it exempted it from the argv table
the gate counts. Both the test and the README now say the count means *backends that drive a
command line*.
