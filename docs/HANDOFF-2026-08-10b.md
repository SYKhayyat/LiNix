# Handoff — 2026-08-10, the session that emptied the register

Five owner rulings and one authorised fix, and the register now holds **nothing open and nothing
built-but-unruled** for the first time. The common shape of what was ruled is worth stating up
front, because three of the five are the same sentence: **a program that does not do what it was
asked, and does not say so.** A version pin dropped in silence. A password prompt nobody can see.
A download with no end.

## The rulings

- **`Q53` — record the version everywhere, replay it only where it can be replayed.** A lockfile
  does two jobs: *reproduce* needs the manager to accept a version, *detect drift* needs it only
  to report one. `lock` keeps recording on every manager; a recorded version becomes an install
  argument only where one can be sent. A pin somebody **typed** that cannot be honoured is refused
  at plan time by name and is fatal under `--locked`. `brew` stops inventing `name@version`.
  (II.53, V.183; closes `S85`.)
- **`Q24` — the user sets the idle bound; 900s stays.** The costs are asymmetric: killing a
  legitimately silent install breaks a machine, waiting on a hang costs minutes. The sharp,
  measured numbers live on reads (120s) and now the sudo prompt (120s).
- **`Y19` — keep it.** A parser that recognises nothing fails instead of reporting an empty
  machine.
- **`S88` — fail fast.** Ruled by the owner in those words.
- **The tag** — ruled: publish a Linux aarch64 binary first, then tag.
- **Unbounded download bodies** — authorised: cap with a config override rather than refuse.

## Things worth knowing before you touch these files

- **`Installable::pins_version` defaults to `false`, and that direction is load-bearing.** A
  backend that says nothing refuses a pin it might have honoured — a message. The other default
  installs the wrong version and reports success. Every `false` owes a row in
  `capability::CANNOT_PIN_VERSION`, and the test fails from **both** sides: a backend with no
  reason, and a reason left behind by a backend that has since learned to pin.
- **The pin refusal needs no provenance flag, and that is deliberate.** Once `apply_locks` stops
  injecting a recorded version into a spec whose backend cannot replay one, a version reaching
  the planner on such a backend can only have been typed by a person. The distinction falls out
  of the mechanism instead of being carried beside it — do not add a `was_hand_written` bit.
- **Separating record-from-replay made a report necessary that did not exist.** The only thing
  that ever compared a recorded version to an installed one was the planner, via the version it
  had injected. The moment injection stopped, version drift on every cannot-pin manager would
  have gone invisible — and the ruling's own claim would have been false in the commit that wrote
  it. The comparison now lives in `check`'s lockfile section and **names** what moved.
- **Three tests were green over a rollback that could not have worked.**
  `a_failed_upgrade_is_reverted_and_never_uninstalled` and
  `a_rolled_back_removal_comes_back_at_the_version_it_left_at` both asserted
  `brew install -- pkg-a@1.0` as the *correctness criterion* — and `pkg-a@1.0` names nothing in
  Homebrew, so on a real Mac that compensation answered *No available formula* and the rollback
  failed. They passed because a mock matches any string. `lock_default_tests` had the same
  problem from the other end: it pinned U11's "a sync converges to the version that was decided"
  using `brew:`, the one manager where converging to a decided version is impossible. It runs on
  `cargo:` now, and two new cases pin `Q53`'s half. **If a test's vehicle is a backend, check the
  backend can do the thing being asserted.**
- **Rollback strips an unmeetable version and says so; it does not refuse.** The compensating
  version is read from the machine, not declared, so the planner never vets it — the check is at
  the transaction's one install site. Refusing would end a rollback with the package uninstalled,
  which is worse than putting it back and naming the version that could not be restored.
- **A closed stdin is not a closed mouth.** sudo, git and Git Credential Manager all ask outside
  stdin — `/dev/tty`, or in GCM's case a *window*. Any future "we set `Stdio::null()`, so it
  cannot prompt" is the same false premise twice.
- **`ssh` was checked and deliberately left alone.** `BatchMode` can only be set from here via
  `GIT_SSH_COMMAND`, which overrides a user's `core.sshCommand` — breaking every working custom
  transport to fix a misconfigured one.
- **`CommandExecutor::as_launched` is public now, not `#[cfg(test)]`.** The integration suite
  registers stubs by that exact string; four registrations in `backend_tests.rs` would have gone
  unmatched on Linux the moment `-n` joined the prefix. Same reasoning as `escalates` being a
  function: one rule, one place.
- **The new CI row cross-compiles rather than asking for an arm64 runner.** A label with nothing
  behind it queues silently for ever (`S86`, 83 minutes); a cross build either compiles or goes
  red. `native: false` says plainly that its tests did not run.
- **Three `if:` conditions in `ci.yml` moved from `matrix.os == 'ubuntu-latest'` to
  `matrix.target == 'x86_64-unknown-linux-gnu'`.** With two ubuntu rows, `os` would have run the
  harness against an aarch64 binary the runner cannot execute.

## Not done, deliberately

- **`S87` is live and untouched.** It is instrumented — the next occurrence carries a `shall why`
  for every package left behind — and two data points still do not settle which timing
  distinguishes it.
- **The tag is not pushed.** Pushing it publishes a release, which is the owner's call. Everything
  it needs is in place: five targets build, and `install.sh` now maps arm64 Linux to the triple
  the release publishes — a new test asserts those two lists agree, because the fallback when they
  do not is silent (build from source, 448 crates, on a Pi).
- **The x86_64 Apple row still builds and does not test**, unchanged and honest.
- The remaining struct-literal backend registrars are still Rust rather than rows in
  `builtin_backends.toml`.
