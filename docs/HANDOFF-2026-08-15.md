## Your brief

**Finish line, and do not stop short of it:** `main` is green in CI, everything is built and
tested for real rather than argued, and a newcomer can go from zero to a working config on the
README alone.

**Rules that bite here** — every one of these has cost this project a day at some point:

- **Verify chain**, in order: `cargo build --all-targets` → `cargo test --no-fail-fast` →
  `cargo clippy --all-targets` → `cargo fmt -- --check` → `scripts/unix-check.sh`. Unverified is
  not done, and a skipped step is a said-so rather than a done. Four of the five steps run on
  Windows and see one platform of two; `unix-check.sh` is the only one that compiles the
  `cfg`-gated blocks.
- **Never run anything over ~30s in the foreground.** Background it and start the next
  independent piece in the *same message*. Never sleep-poll. The suite is ~20 minutes, an image
  build 15–30, the container harness another 10.
- **Docker runs inside WSL here**: `wsl -- docker`, `MSYS_NO_PATHCONV=1`, `/mnt/c/...` paths, and
  **pass scripts as files, never as quoted command strings** — the failures are silent.
- **Push once, then watch that run.** A second push cancels the first, and cancelled is not red.
- **Stop and ask only for** a register ID (`D*/W*/K*/N*/T*/U*`), a user-noticeable behaviour
  change, removing a feature, or Part II looking wrong. Everything else: decide, and put the
  reasoning in the commit message.
- **Fix the family, not the instance.** A bug is a representative; find the sibling in the
  adjacent path, the twin adapter, the other config layer, and fix them in the same change. Say
  which siblings you checked, including the ones you ruled out and why.
- `J2` and `J3`'s reversible half are OPEN in `docs/spec/decisions.md` and are **the owner's**,
  not yours. Do not answer a decision in code.

## Lessons this round paid for

1. **A gate that reports what it measured, and asserts only that nothing it measured is wrong, is
   satisfied by measuring nothing.** Both halves of the terminator probe's contract were true on
   a run that had quietly stopped checking a row. The fix is not a better assertion about the
   findings — it is a record of what this host *owes*.

2. **A ratchet over a count cannot see a swap.** Seven rows measured was never the claim;
   measuring *these* seven was. Any gate whose subject is a set should ratchet over names.

3. **A matrix slot named for the run must be consulted by every step of the run.** `matrix.flags`
   reached the lifecycle step and not the probe step, so an image's one requirement for running
   at all was in force for half of its job. The same shape appeared three times this round.

4. **Push, then read the run.** Four legs red, and three of them were invisible from this machine:
   openSUSE's missing `cmp`, the Windows guard test, and the storage version drift. The two
   sections that caused two of them were verified locally on ubuntu and arch, which is exactly the
   coverage that makes a defect look absent.

5. **A CI job that appears in every job list is not a gate until it has produced an answer.** The
   mutation job was cancelled at its six-hour timeout on three consecutive nightlies while
   reading as a gate that ran. Its first completing run found a real hole in the first file it
   finished.

6. **Two prior measurements that disagree are usually two different machines.** CI measured five
   rows on arch where local measured seven; the honest answer was not "one of them is wrong" but
   "the image gained `yay` and `paru` in between". Check what changed about the host before
   deciding a number is a bug.
