# Handoff — 2026-08-10, the day the release turned out not to be cuttable

Three owner rulings landed, and then a run of eight bugs whose common shape is worth stating
before any of them: **a check that runs and reports to nobody.** CI unparseable for ten commits,
a matrix building one target of four, a nightly job red for six nights, a release job waiting on
a runner that no longer exists. None of them made anything go red that a person would see.

## The two things that are the owner's

1. **`Q53`** — what a version pin means on a manager that cannot express one. Measured, written
   up with a recommendation, deliberately not decided in code. It is the only open question in
   the register.
2. **The tag.** `git tag -a v0.8.0 -m "..." && git push origin v0.8.0`. The release job is
   `needs: build` and fires on `v*`. As of this session the four builds it needs can all run,
   which was not true this morning.

## The rulings

- **`Q49`/`Q50`** — pip stops losing to PEP 668; `heal` unwedges a killed package manager, waits
  for the manager it is recovering from, and says what it left alone.
- **`Q51` — ruled: wait.** Another package manager holding its own lock made LiNix fail in 3.5
  seconds with a sentence that was false in exactly that case. It waits now, with three verdicts
  and a budget shared across retries.
- **`Q52` — ruled: every child has an owner, through one of three doors.** SIGKILL for a package
  manager mid-transaction, and seventeen sites that detached a child or parked a runtime worker.
  SIGTERM with a grace period, then the hammer.
- **`N8`** — a ceiling per category and one over all of them. The register had recorded `N8` as
  *unasked*; it had been asked under `Y20` and ruled the same day.
- **`Q53`** — raised, measured, **open**.

## Things worth knowing before you touch these files

- **A GitHub job asking for a withdrawn runner label queues for ever. It does not fail.** No
  error, no annotation, nothing to open. `no_workflow_asks_for_a_runner_github_has_withdrawn`
  keeps the retired labels because nothing in a workflow run will ever report one.
- **`ci.yml` is parsed by `cargo test`, not only by GitHub.** A workflow that does not parse
  produces no failing check — the failure mode is silence, not red. Every `run:` value ending in
  a colon needs quotes; this cost ten commits once and nearly recurred the same day.
- **A registry walk is `cfg!(target_os)`-shaped.** Anything auditing "every backend" from a test
  must read the source or call the registrars directly, or it audits whichever backends happen to
  register on the host — which is exactly how dnf's exit-policy defect survived a passing suite.
- **CRLF.** Most of `src/` and the spec files are CRLF. A Python heredoc doing `.replace()` with
  `\n` matches nothing and reports success. It bit twice today, including once *after* the lesson
  was written down. Use the editing tools, or detect the ending first.
- **`scripts/decision-count.sh --check` is not optional.** Adding `Q53` left eight numbers in
  `SPEC.md` and `decisions.md` disagreeing with the register, and the script found all eight. Run
  it before committing anything that touches the register.
- **`guard::preview_refusals` is the single implementation of "what will `apply` refuse".**
  `verbs/plan.rs` calls it; do not re-derive it there.
- **`enforce_additions` does not run on a preview** — a dry run reaches the phases with an empty
  ledger, so a gate there computes a fraction of the real total.

## Not done, deliberately

- **`S87` and `S88` are live.** `S88` in particular is a fifteen-minute hang a real user can hit
  by mistyping a password; it belongs to `Q52`'s family from the other end — not a child LiNix
  abandons, a child LiNix waits on for ever.
- The four backends that could pin a version and do not (`xbps`, `pkgin`, `pkg`, `pkg_add`) are
  under a ceiling in `a_version_pin_is_honoured_or_explained_tests`. Lower it as they land.
- The cross-compiled `x86_64-apple-darwin` row **builds and does not test**. An x86_64 test binary
  needs Rosetta on an arm64 host, and a tick that may or may not have run the suite is worse than
  an honest absence. The suite for that OS runs on the arm64 row.
- **Linux aarch64 has no published binary.** Still the most obvious gap in the release.
- The remaining struct-literal backend registrars are still Rust rather than rows in
  `builtin_backends.toml`.
- A cap on unbounded download bodies (`github.rs`, `web.rs`, `appimage.rs`).
