### `N8` — ruled 2026-08-10

**A ceiling per category and one over all of them.** `max_port_closures` (20) takes ports out of
`max_extra_removals`; `max_total_changes` (0, off) counts every change one command makes —
installs and upgrades, removals of every kind, resources written, ports opened and closed.

**The register was wrong about the question, and the entry now says so.** `N8` was recorded as
*unasked*. It had been asked, under `Y20`, and ruled the same day. The reviewer searched the `N`
series; it was living in the `Y` series, because it arrived through the removal-guard work rather
than the firewall work.

### The adapters ruling

A malformed `adapters/*.toml` still warns and is skipped mid-`sync`. `check adapters` is the
ninth section and exits non-zero on any surface written and not in use.

### `S80` — the release surface

**CI had not executed a step in ten commits.** A step ending in `pty_tests::` made `ci.yml`
unparseable, which fails the *run* — zero seconds, no job, no log. `every_workflow_value_that_
yaml_would_read_as_a_key_is_quoted` is the gate.

**The release job had never run** and would have published one binary four times, because a
release asset takes the file's basename and all four targets build `linix`/`linix.exe`.

**Both installers fetch the published binary** and fall back to a source build.

## The one thing left for the owner

**Push the tag.** Everything is committed and pushed; the release job is `needs: build` and fires
on `v*`. Nothing else is waiting on anyone.

`workflow_dispatch` on the CI workflow is a rehearsal: it downloads the same artifacts, runs the

## Things worth knowing before you touch these files

- **`ci.yml` had never been parsed by anything in this repo.** It is now, in `cargo test`. A
  workflow that does not parse produces no failing check to notice — the failure mode is
  silence, not red.
- **`guard::Reaping` is the command's ledger for every change, not just removals.** `so_far(kind)`
  for the three removal kinds, `changes_so_far()` for the total. Only the `enforce*` family
  writes to it. `inspect_removals` takes the ledger, never a number — `already: usize` was the
  `S55` shape and it had survived one level up, in the `plan` preview.
- **`guard::preview_refusals` is the single implementation of "what will `apply` refuse".**
  `verbs/plan.rs` calls it. Do not re-derive the answer there; that is what drifted before.
- **`enforce_additions` does not run on a preview**, and the comment above it says why: a dry run
  reaches the phases with an empty ledger, so a gate there computes a fraction of the real total
  and would say yes where the run says no.
- **`app::check::Section::ALL` is nine now.** The docs table in `target-state.md:1210` names them
  and is maintained by hand.
- **CRLF.** Most of `src/` is CRLF. A Python heredoc doing `.replace()` with `\n` matches
  nothing and reports success — it cost two edits this session before the pattern was applied.

## Not done, deliberately

- The remaining struct-literal backend registrars (apt, pacman, dnf, winget, scoop, choco, mas,
  pip, gem, bun, macports, pkgin, the BSDs, dotnet, conda, yay/paru) are still Rust rather than
  rows in `builtin_backends.toml`.
- A cap on unbounded download bodies (`github.rs`, `web.rs`, `appimage.rs`). Still a ruling
  rather than a refactor.
- **Linux aarch64 has no published binary.** The build matrix is four targets and that is not one
  of them, so an ARM server falls back to compiling. It is the most obvious gap in the release.
