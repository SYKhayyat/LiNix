## Q4's release blocker is closed, and `zfs` was the last name in it

`zfs` was the one backend with no real lifecycle in any harness and no stated reason. It now
completes a real install → list → uninstall → gone on the `storage` image, measured on CI run
**32132445664**: `8 real lifecycle`, `pass=378 fail=0`. `LIFECYCLE_GAP_CEILING` is **0** and the
storage floor is **8**, both read off that run.

**Neither obstacle was a defect in Shall, and neither was what anyone assumed.** Recorded here
because both assumptions are the kind that get re-made:

1. **A GitHub runner already carries a ZFS module** — 2.3.4-1ubuntu2, by some route other than
   `linux-modules-extra`, which *was* measured and ships none (2842 files, zero ZFS, same for the
   generic flavour). A step that built OpenZFS 2.4.3 against the runner's kernel headers was
   written, it compiled, and it was **deleted**: it produced a different version from the one the
   host had loaded, and 2.4.3 tools against a 2.3.4 module fail `zpool create` outright. The
   image now builds its userland at the version read off `/sys/module/zfs/version`, so a runner
   image that moves to 2.5 takes the tools with it and there is no constant to update.
2. **The pool has to be built on a loop device**, not on a file in the container's overlay
   filesystem — which is what the `btrfs` and `lvm` probes beside it had done since 2026-07-31.
   The `zfs` branch was the sibling nobody came back to, and it also swallowed the error that
   would have said so, exactly as the lvm probe used to before 2026-07-31.

**Two instruments earned their keep on their first run and both are worth keeping in mind.** The
userland/module version check turned a mystifying `zpool create` failure into one line naming
both numbers. And it then cried wolf on `2.3.4-1` versus `2.3.4-1ubuntu2` — the same OpenZFS with
different packaging — so it compares the upstream version only now.

**A ceiling of 0 needs the exemptions to name themselves.** Section 13c already detected a kernel
with no btrfs, no device-mapper or no ZFS module; it records the fact now and
`no_lifecycle_reason` reports it. So a kernel that cannot is an exemption detected at run time
and named (`Q17`), while a device *this run failed to build* stays in neither table and fails the
run by name. Done for all three storage effectors, not for `zfs` alone: btrfs and lvm carry the
identical branch and would have had the identical hole on the first host without device-mapper.

## The overlap floor was a target wearing a detector's clothes

`Mutation (the transaction 2/4, nightly)` failed its **unmutated baseline** on dispatch
32136919193 — `cargo mutants` exit 4, not a surviving mutant — on
`sbom_asks_the_managers_concurrently`: `1.4x` overlap against a `1.5x` floor, 21 children, 5
waves.

**The mutation job is the only place any timing gate is measured on a contended host**, because
`cargo mutants -j2` runs the whole suite as its baseline with a second suite beside it. Two other
shards of the same tree passed, and so did the control (`list`) on the failing shard.

`min_overlap` is **1.25** now. 1.5 was read off healthy hosts, where the lowest legitimate
reading is 2.0; a serial fan-out has an exact signature of ~1.0, and 1.4x is 40% above it. The
wave ceiling is untouched — it is the load-independent half of the pair and it passed on the run
that failed. This is the **third** time a number on this rule was set from one class of host and
went red on another; the doc block carries all three readings.

## What is left

1. **`shape_violation` has no caller in `src/`.** The fan-out rule is implemented once as that
   pure function and again inline in `tests/latency_budget_tests.rs` and
   `tests/the_other_fan_outs_fan_out_too_tests.rs`. That is the duplication this repo removes
   rather than reconciles, and the tests should assert *through* the function. Deliberately not
   done in release week.
2. **`Mutation (the transaction 2/4)` has not been green on today's tree.** It died at baseline
   before testing a single mutant. `git diff 5de1a1f..HEAD -- src/core/transaction.rs tests/` is
   empty, so its mutants were verified on byte-identical source and tests by dispatch
   32062212949 — an inference, not a run. A confirming dispatch was started on `768a004`
   (**32151006346**); read it rather than assuming.
3. **The release page itself.** A green release job is not seven downloadable assets; that
   distinction is what `0.7.0` and the first `0.8.0` write-up each got wrong in a different way.
   Confirm the assets on the release, and that `install.sh` on a clean host takes the musl
   binary rather than compiling 448 crates.
4. **The version check compares upstream versions**, so a genuinely mismatched *packaging* of the
   same upstream release will pass it. That is the right trade today and worth knowing.

## Traps this session cost time to, all local to this machine

- **`git push` from WSL hangs for ever.** WSL git has no credential helper, so it blocks on a
  prompt nobody can answer. Push from Windows, where `credential.helper=manager` has the
  credentials. Read CI from WSL with `curl` against the REST API — `gh` is installed nowhere.
- **Unauthenticated API polling is 60 calls an hour.** Three concurrent watchers exceed it and
  the JSON that comes back has no `status` key, which reads as a crash. Poll every two minutes,
  or read the token out of the credential helper.
- **git-bash rewrites `/mnt/c/...` into `C:/Program Files/Git/mnt/c/...`** when it is an argv
  path. Quote it inside `bash -lc "..."`, where it is a string rather than a path.
- **Nested quoting into `wsl -- bash -lc` breaks on `$(...)` and nested quotes.** Write the
  script to a file and run the file. This is written down in the project memory and was ignored
  once here anyway.
- **A `<<'PY'` heredoc through this shell eats backslashes**, so a Python replacement whose
  anchor contains `\` silently matches nothing. Use the Edit tool for those, or anchor on text
  with no backslash in it.
- **`cp -a <DESTDIR>/. /` cannot work on Ubuntu.** `/lib` is a symlink into `/usr` and `cp`
  refuses to replace it with a directory. Copy into the target directory, not onto `/`.
