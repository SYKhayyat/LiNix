## 4. The finding that outranks the stall — FIXED

`with_manager_policy` attaches a manager's `ExitPolicy`. `register_generic` applies it; **sixteen
registrars call `reg.register` directly and never did**: `apk apt aur_helper bun choco dotnet gem
macports mas pip pkg_add_openbsd pkg_freebsd pkgin scoop winget zypper`.

So those backends ran on `ExitPolicy::default()` — no failure, permanent or absent markers.
Measured before the fix:

```
scoop install <nonexistent>  ->  linix-failure-class: unknown   ->  still declared
```

Q1 (2026-07-27) withdraws a declaration when the failure is permanent. It never fired. The dead
line then failed **every later install**.

**I first attributed ten of the run's thirteen failures to this, and that was wrong.** The
confirmation run with the fix in shows the leftover gone and `nimble` newly classified
`permanent` — so §4 is real — while `bun`, `dotnet`, `pnpm`, `winget` and `yarn` still fail, on
`sc` **1056** (`Q39`). There were two cascade sources and Q39 is the bigger one. A cascade with
one identified source is not a cascade with one source. Worse and never exercised: scoop's
policy exists because *scoop exits 0 on every outcome*, so without it a failed scoop command reads
as a success.

**After the fix:** `linix-failure-class: permanent`, declaration **withdrawn**.

**The guard test had been green the whole time and could not fail** — it called
`with_manager_policy(core)` *inside its own assertion*, proving the helper works and never asking
whether a registrar calls it. Replaced with a source scan (the `prompt_guard_tests.rs` idiom,
because the defect is a missing line), proved to fail by removing one fix and watching it catch it.

## 5. Decisions I made without asking, and why — all reversible

1. **Harness gets `exec < /dev/null`.** An automated sweep must not hand a keyboard to something
   with nobody at it. Invisible outside the program, so mine per CLAUDE.md.
2. **…with `LINIX_IT_KEEP_TTY=1` to put it back.** A fix that also deletes the only way to
   reproduce a bug leaves nobody able to show it existed, or to notice it returning.
3. **The stall capture photographs and never kills.** Killing is what destroyed the evidence four
   times. It samples CPU across a window, because one frame cannot tell slow from stuck — and two
   of the three captures would have been misread without that.
4. **Fixed all sixteen registrars, not the three Windows ones I had measurements for.** "Fix the
   family" is binding. It restores ruled behaviour (Q1) rather than inventing any. **This is the
   broadest change and the one to reverse first if something regresses off-Windows** — on `apt`,
   `zypper`, `apk`, `pkg_freebsd` I have the identical code shape and no run.
5. **The Q32 test is committed `#[ignore]`d.** It fails correctly; Q32 is OPEN and its fix changes
   when a command reports failure. Better a named ignored test than a red tree or a silent gap.
   **Remove the ignore in the same commit as the fix.**
6. **Did not fix Q32/Q33/Q37 themselves.** All change behaviour a user notices and carry register
   IDs. Recommendations are written; the rulings are the owner's.
7. **Raised the harness-vs-product disagreement rather than picking a side** (does a failed
   install's name leave the manifest). `GRADE-2026-07-28` E2 says that assertion was deliberately
   pointed at the product. It turned out the product was right to keep it *and* the classification
   was broken — §4 is why.

## 10. The method note, because it is the transferable part

Everything here came from measurement refusing a story. Four theories were produced by reading
code — three before this session, one mine — and all four were wrong, while 1617 tests stayed
green throughout. Several defects had a test written *specifically for them* that could not fail;
two of those I wrote myself this session (a fixture Windows rejected for bad quoting, so the test
passed in 0.06s proving nothing; and a probe whose `pgrep -f linix.exe` never matches a native
process from msys, so it took zero snapshots and said nothing was wrong).

**The recurring defect class in this repo is a check that cannot fail.** Watch it fail first.

### Why reading misses these

Every one of them looks correct locally, which is exactly why code review — human or model —
does not find them:

- `wait_watched` **has** a bound. You have to notice the bound ends before the read begins.
- `with_manager_policy` exists, is called, and its own comment says *"so no registrar can forget
  it."* Sixteen forgot.
- `deploy_executable` refuses correctly. The defect is the **order it is called in**, which is not
  visible anywhere inside the function.

Asked "why is this slow" or "why does it hang", any competent reader produces a plausible
mechanism, because producing one is what the question rewards. Four were produced here — three
before this session and one during it — and all four were wrong. The difference was never better
reasoning. It was `ARM C rc=0 elapsed=64s`.

### What to demand, to catch the rest

1. **A number, not an explanation.** "Show me the measurement" killed four theories. An account
   with no measurement attached is a draft, whatever its prose quality.
2. **Arm the instrument before the run.** Evidence with a short half-life — a wedged process's
   child list — does not survive being written up afterwards. Four opportunities destroyed it.
3. **Self-test the instrument against a known case** before trusting it on an unknown one. Two of
   this session's instruments silently did nothing until that was done (T2, T3 above).
4. **Treat green as a claim.** 1617 tests passed while all of this was live, several of them
   written specifically for the defects they missed. Ask to *watch a test fail*.
5. **Refuse "unknown".** Every entry that got pushed on turned into a diagnosis: Q37, Q36, the
   seven open operations, and §4 — which is the largest finding here and arrived after a document
   claiming to be complete had already been written.
6. **Ask for the family, not the instance.** "Fix the whole family" turned 3 registrars into 16,
   and one download backend into three.
7. **Require the run to finish unattended.** A run that needs a human to unstick it is not a
   measurement of anything. This sweep had never once completed before this session.
