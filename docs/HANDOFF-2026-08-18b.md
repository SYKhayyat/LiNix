# Handoff — 2026-08-18b: the concurrency and efficiency audit, built

**Read `docs/SPEC.md` first.** This file is the state of play, not the map.

`docs/AUDIT-2026-08-18-concurrency.md` asked three questions of all 367 source files — what costs
more than it needs to, what blocks when it should not, what races — and returned 27 findings under
a green suite and a clean linter. **Twenty-three are built. Four are with the owner.** Nothing
here is a partial fix waiting to be finished.

---

## The four that are the owner's

They are `L1`–`L4` in `docs/spec/decisions.md`, all **OPEN**. The register now reads **223 entries,
four open**, and `scripts/decision-count.sh --check` agrees — it caught every stale figure in both
files on the first run, which is what it is for.

- **L1** — does the WAL flush per package on *success*, or once per wave? The *opening* half is
  batched already, because that is free: `record_starts` writes a whole wave's entries and flushes
  once, and every entry keeps the guarantee it had. The closing half is a durability trade-off — a
  crash between "installed" and "recorded" costs one idempotent re-run, which
  `app/sync/mod.rs` already relies on for recovery — so it stopped here.
- **L2** — are the six `locks/` ledgers protected by the data lock, by writer scope, or by
  nothing? They live outside the directory `DataLock` covers. What protects them is two unrelated
  accidents, and the regex lock was what that looks like when half of one is missing.
- **L3** — do reader commands accept a torn cross-file view? Milliseconds wide, advisory output,
  almost certainly invisible. Raised because the argument for a *directory* lock for writers is
  the same argument for readers, and only one conclusion was drawn.
- **L4** — **Part II describes a locking model the code deliberately no longer has.** II.8 says
  every mutating command holds the lock for its whole run; `LockScope` has had three scopes since
  `watch` bricked the CLI of whoever followed the documented deployment. `LockScope`, `Deferred`
  and `Reader` appear nowhere in `docs/spec/`. **Not fixed here** — `CLAUDE.md` says do not fix
  Part II.

Each entry carries a recommendation. L2, L3 and L4 are really one question, and answering them
apart is how they drifted apart.

## What the audit got wrong, which is the part worth reading

**The audit's "the family is two, and both are listed" was false.** `github.rs` and `web.rs` both
had the lost-update race — load under the lock, release, download for seconds, save under the lock
again — and so does **`appimage.rs`**, which the audit's family check missed. It is the worst of
the three: `github` and `web` at least took a lock for each half; appimage had none at all. All
three now keep one in-memory map behind one lock, merge only what a call changed, and write once
per call. Two `web:` installs racing each other is now a unit test, in-process, with the delays
that make it reproduce.

**The new II.52 gate found three sites the hand audit did not** — `profile.rs`, `plan.rs`,
`setup.rs`, all one-shot durable writes at the end of a command. They went through
`utils::file::persist_off_the_runtime` rather than into an exemption table, so
`ON_THE_RUNTIME_BY_DESIGN` is **empty** and the rule has no exceptions to remember. That is the
argument R8 makes about lock keys, applied here.

**Three of the suite's own meta-gates then caught this work**, which is the best thing that
happened all session:

- `executor.rs` crossed 3,000 lines. `Capped` moved to `src/core/capture.rs` — "what a captured
  stream keeps" is not the same subject as "how a child is owned and stopped". Now 2,985.
- `every_setting_the_config_declares_is_read_somewhere` reported `GuardSettings::matchers` as a
  dead setting. It is a `#[serde(skip)]` cache, not a setting. **The gate was improved rather than
  the field exempted**: a field serde never reads cannot be written in `preferences.toml`, is not
  documented, and has no user to disappoint, so counting one is a checker crying wolf.
- `no_public_function_is_referenced_by_nothing_at_all` found `clean_cached` orphaned once its one
  caller moved to `clean_cached_set`. Deleted. There is deliberately no one-name sibling now:
  taking a set is what makes I9 impossible to write again.

**And one regression this work introduced and closed before it shipped.** The three artifact
backends never check `--dry-run` themselves — they rely on `persist` refusing the write. With a
per-call file read that was enough; with a memo it stopped being, because a preview's change would
survive to the next question *in the same run*. The merge now happens on a copy that only a run
that acts adopts.

## The gates that did not exist

The audit's sharpest section is *"Why the suite is green"*, and its one sentence is worth keeping:
**the suite polices the seam, not the use of the seam.** Five enumeration gates all ask "does this
site go through the door?", and every serious finding was a correct call to a correct door made at
the wrong moment or in the wrong scope.

Four new ones, each closing a finding *and* its class:

- **`a_blocking_wait_is_off_the_runtime_tests.rs`** — the second half of II.52, which had no gate
  at all. A durable write or a filesystem walk reached from an `async fn` without
  `off_the_runtime`/`spawn_blocking` fails the build. **Its non-vacuity control is different from
  its five siblings' on purpose**: the answer this gate wants is *zero*, so "the walk matched
  something" cannot be the control. `the_predicate_catches_what_it_is_for_and_nothing_else` runs
  the same predicate over a planted file holding one of each shape and requires all three caught,
  and none of the fixed forms.
- **`a_reader_writes_nothing_tests.rs`** — thirteen `Reader` subcommands leave the fixture
  byte-identical. It is the *sibling* of `a_preview_leaves_the_config_byte_identical` and not a
  case in it: that test's own non-vacuity control demands the verb change something, so no
  `Reader` can ever be one of its cases. This one brings its own control. One write is excused
  with a sentence — `shall-plan.json` is `plan`'s answer, not state — and a third test fails if
  that write stops happening.
- **`a_fed_child_is_drained_while_it_is_fed_tests.rs`** — a 512 KiB payload to a child that never
  reads stdin and writes past its own pipe buffer. Before the fix this does not return slowly; it
  does not return.
- **`every_semaphore_says_what_scope_it_caps`** in `fanout_cap_reads_the_setting_tests.rs` — the
  sibling assertion R5 needed. The old gate checks a cap's *value*; nothing checked its *scope*.
  Nothing static can prove a semaphore is shared, but a new one whose owner nobody has named now
  fails.

Plus behavioural regressions where they were cheap: two concurrent `web:` commits keeping both
records, the listing memo refusing a pre-invalidation answer, `essential()` asked once and
forgotten with the listings, `append_lines` ordering and torn-tail repair, `Capped`'s head/tail.

**`MockExecutor::set_delay` is still the unused instrument the audit names.** It has a `delays`
map described as *"for tests about concurrency rather than about output"*, used on two *read*
commands in one file. The new race tests use plain `tokio::time::sleep` at the point that matters,
which reproduces R1 without touching it — but the audit is right that pointing `set_delay` at a
mutating command is what would make the whole R-class reachable through the normal fixture.

## Verified

`cargo build --all-targets` → `cargo test --no-fail-fast` → `cargo clippy --all-targets` →
`cargo fmt -- --check` → `scripts/unix-check.sh`, on Windows, in that order.

**`unix-check: ok`** — the tree compiles for Linux in `rust:1-slim`, which is the only step that
sees the `cfg`-gated blocks the other four cannot.

**Not measured.** Every number in the audit is derived from constants in the source, and so is
every number here. Nothing was benchmarked, no container harness leg was run, no deadlock was
reproduced against a real manager. The changes are each argued from a mechanism, and the ones with
a behavioural test have one; that is a different claim from "this is faster", and the difference
is the repo's own standard.

**Two things only the container harness can settle**, both named by the audit and both still open:

- **B1's premise.** The hook re-entrancy fix no longer depends on `SHALL_INSIDE` surviving `sudo`
  at all — a `hook-*` subcommand now `try_lock`s and stands down rather than waiting 120s — so the
  fix is correct whether or not the marker travels. But *that the marker does not travel* is still
  unverified by running anything. The two-second version is
  `sudo -n sh -c 'printenv SHALL_INSIDE'` from a process that set it.
- **R4.** Concurrent `sudo` priming is serialised now, and nothing in either instrument exercises
  the `sudo` path: the Rust suite mocks the executor, and the container harness runs as **root**,
  where `escalates()` is `false`. A non-root leg with passwordless sudo covers B1 and R4 at once
  and is the highest-value change to the test apparatus in the whole report.
