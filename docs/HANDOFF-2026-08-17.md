# Handoff — 2026-08-17: the nightly's three reds, and the gate that could not have caught one

**Read `docs/SPEC.md` first.** This file is the state of play, not the map.

The previous handoff (`-16e.md`) left five things and said the next nightly would answer one of
them. It did. This round read that nightly, fixed two of its three failures at the root, and
took two thirds of the third.

**The push run was green the whole time.** `66b1333` passed every job a push runs. What was red
is the scheduled run — eleven jobs a push never touches — and that distinction is the first
thing to establish before treating a red board as a broken tree.

## What is left

1. **Fifteen surviving mutants: fourteen in the async execution engine, and one that cannot be
   tested the obvious way.** Twenty-seven of the nightly's forty-two are dead and verified.

   The odd one out is `guard.rs`'s `before != report.objections.len()`, whose only observable is
   a `warn!`. A test for it was written, verified to kill the mutant, pushed, and **withdrawn
   the same day** — read the paragraph now standing above `allow_the_count`. Asserting on
   `tracing` output from the lib test binary is a race: callsite `Interest` is cached globally
   and other tests create and drop dispatchers on other threads throughout the run. Measured,
   not suspected — the capture came back empty in **2 of 3 identical Linux runs**, while passing
   every time on Windows and every time when the test ran alone. That is precisely the flake
   profile that gets a whole suite ignored. Killing it wants the announcement to be a value
   something reads rather than a line something overhears, which is a shape change to a report
   two call sites share.

   The other fourteen need mock-backend plumbing in `batching_tests`' harness to reach, which is
   why they are a job rather than an afternoon. Current line numbers, re-read after this round's
   edits shifted the file by two:

   | Line | Mutation | What it changes |
   |---|---|---|
   | `449` | `-` → `+` | `total_nodes - completed_indices.len()`, the telemetry shape. Invisible unless a run starts with nodes already complete, which is a resume. |
   | `503` | `&&` → `\|\|` | `!dispatching.is_empty() && in_progress.is_empty()` — the wave counter. Over-counts under `\|\|`; the existing `waves <= depth` assertion does not catch it. |
   | `567` | `&&` → `\|\|` | `*n == 0 && !completed.contains(&dependent)` — a node could be dispatched with dependencies outstanding. |
   | `655` ×3 | `&&` → `\|\|`, `<` → `==`, `<` → `>` | the "DAG Logic Stall" detection. |
   | `1029` | `&&` → `\|\|` | `is_install && …pins_version()` — the rollback version-strip gate. |
   | `1032` | delete `!` | `\|i\| !i.pins_version()` — same gate, inverted. |
   | `1038` ×2 | match guard → `true` / `false` | `Some(v) if concrete_version(&v)` — this is the `brew` `pkg-a@1.0` bug's own guard. |
   | `1125` | `+=` → `-=` | `lock_waited += spent` — the one budget across the whole retry loop. |
   | `1172` | `&&` → `\|\|` | `config.purge && handler.supports_purge()` — a non-purge run would purge. |

   `1029`/`1032`/`1038` and `1172` are the interesting ones: they are the branches that decide
   *what argv a rollback or a purge sends*, and `1038` guards the exact defect that shipped a
   non-existent formula name to a real Mac. They want a mock backend that records the calls it
   received and answers `pins_version()` and `supports_purge()` both ways.

2. **Four individual mutants timed out.** Shards `transaction 1/4` and `3/4` exited 3 rather

   mutant that survived, and it is not reported as either.

3. **`gentoo/stage3:latest` will drift again.** This round pinned what the leg depends on, and
   the pin is a `:latest` tag of its own (`gentoo/portage:latest`). The tree it carries is

   the difference that matters — but nothing here digests it. If the leg reports something

4. **A terminator-floor ratchet is owed, and deliberately not taken here.** With the portage

   It is not ratcheted because that is one local run, and ratcheting a gate on a single
   measurement is precisely the mistake item S91 records — the same paragraph that says to take
   the largest number from a **full matrix run**. Take it from the first nightly that runs this

## What this round finished

### The gentoo leg, which had been measuring whatever Gentoo published that day

`pass=238 fail=0` on 2026-08-16 and five failures plus an exit 127 on 2026-08-17, on a commit
that touched nothing it runs. The runtime stage is `FROM gentoo/stage3:latest` and that tag is
rebuilt daily.

**Probed rather than reasoned about.** On 2026-08-17 the image has no `/var/db/repos/gentoo` at
all; Portage says the `repos.conf` location does not exist and `emerge --search '^jq$'` answers
`[ Applications found : 0 ]`. Every check that asks Shall to resolve a bare name then fails with
*"no package manager this line accepts has `jq`"* — the dry-run plan, all three chain forms, and
`info`. Five failures reading like a broken resolver, and it is an empty tree.

**Shall was right the whole way through, and this is worth keeping.** With the tree mounted
back, `emerge --search '^jq$'` returns two ebuilds and Portage itself refuses bare `emerge jq`
as ambiguous between `app-misc/jq` and `dev-python/jq` — while Shall's own plan says
`emerge:app-misc/jq`, the correct atom. The one check that passed throughout was the one that
names the category.

The fix pins the tree from `gentoo/portage`, symlinks `/etc/portage/make.profile` under a
`test -d` so a profile renumbering fails the **build** naming the directory, and suppresses
Portage's news notice — via `news-gentoo.skip`, not `.read`, because `.unread` is regenerated
from the tree on the next command unless the item is skipped. The first attempt used `.read` and
did nothing, which the container said immediately.

**Second half, same cause.** The argv-probe step invokes `cargo test` in the image and got
`cargo: command not found`. The image had `cargo` the day before and had it again hours later —
both measured. The comment above that step claimed *"the image already carries a Rust
toolchain"*, which was a statement about all four images in the matrix and false for two.
`Dockerfile.guix` had already solved this for `metacall/guix`: build the suite in the Ubuntu
builder and copy the binary in. Gentoo does that now, and the guix leg is **green in the same
nightly this one failed in**, so the pattern is precedent rather than hope.

### A coverage ceiling ten wider than the number it bounds

`nixos:` shipped on 2026-08-16 in neither harness's `canary()` nor its `no_lifecycle_reason()`.
The macOS and Windows legs, whose ceiling is 0, went red by name — the gate working exactly as
designed. Every container image printed a `soft` line and passed, because that harness's ceiling
was **11**.

The file said what to do about it — *"take the largest of them from the next full matrix run and
lower this line to it"* — and nobody had. Read off eleven images' own soft lines rather than
reasoned about: push run `31990107008` for ubuntu, arch, alpine, void, fedora, opensuse and
storage; nightly `31992721802` for tools, slackware, guix and gentoo. Every one printed `nixos`.
Only `storage` printed anything else — `zfs`, which genuinely has no canary on the one image
where `SHALL_IT_STORAGE` is set.

A ceiling ten above the number it bounds is not a lax gate, it is an absent one: the next ten
backends could each have arrived with no lifecycle and no stated reason. Lowered to 1, with the
eleven measurements recorded beside it.

### Twenty-seven mutants, each verified by hand

Not "wrote a test and the suite is green" — for every one, the mutation was applied to the
source, the test was run, and the failure was watched. That step is not ceremony, and two
existing tests are why:

- **`the_removal_ceiling_fires_past_the_limit_and_not_at_it`** was written nine days ago
  specifically to kill `too_many_changes`'s `>`→`>=`, and does not. It sets `max_removals`, a
  per-kind ceiling checked elsewhere, so the function it names never saw a total equal to its
  limit. The mutant was alive the whole time under a test named for it.
- **`pinned_only_requires_a_concrete_version`** asserted `os.len() == 2`. Flipping
  `v != "latest"` to `==` reverses the verdict on every line and leaves the count at two:
  `@version=latest` passes as pinned, `@version=1.6` is refused as floating. **A count is
  invariant under a permutation, which is exactly what a comparison flip produces.**

What got covered, and why each was reachable at all:

- `guard.rs` (5 of 6): the capped list at exactly `MAX_LISTED`; the `max_total_changes`
  boundary, asked of the function that owns it; `pinned_only` by identity; and
  `describe_objection`, whose entire body could be replaced with `"xyzzy"` without failing
  anything. The sixth is item 1 above.
- `Transaction::batches` (8): **it had no direct test at all.** Every batching test drives the
  async harness and asks how many *commands* ran, never where the split fell — which is the whole
  of the arithmetic. The new test picks name lengths so each mutation moves the answer: 99 (cost
  100) puts 60 names at exactly 6000 bytes, the one place `>` and `>=` disagree; 100 (cost 101)
  fits 59 where cost 100 or 99 would fit 60, which is where dropping the `+ 1` shows up.
- `TransactionConfig::from_config` (4): `..Self::patient()` makes a deleted field
  indistinguishable from a read one. `max_concurrent` is asserted at **two** values, because the
  fallback is the host's parallelism and one value can agree with it by luck.
- The retry arithmetic (10), via two extractions that stand on their own:
  - `retries: attempt - 1` was written inline in three `TaskResult` constructions, so one
    subtraction produced six survivors. **A copy of an expression is a copy of its blind spot.**
  - The backoff was a shift inside a multiplication inside a `min` inside a match arm: three
    separate numbers, all three unreachable. Now `backoff_for(attempt, initial, max)`.
  - `falsify_transience`'s `attempts < 2` reads `<= 2` because its tests use 3 and 1 and never
    2 — the only value where the two spellings disagree.

## Lessons this round paid for

- **A red board is not a red tree.** Check `--event` before anything else. The push run was
  green at the same SHA; three nightly-only jobs were red for three unrelated reasons.
- **Probe the base image before blaming the product.** One container answered in ninety seconds
  what the failure text pointed the wrong way about, and the alternative was a six-hour nightly.
- **A test named for a mutant is not a test that kills it.** Both of this round's corrections
  were tests that read as coverage. Apply the mutation by hand; it costs one `sed` and one
  `cargo test`.
- **A count is invariant under a permutation.** Assert identities, not lengths, wherever the
  thing under test is a decision about *which*.
- **A ceiling nobody re-measures stops being a gate.** This one had an instruction sitting above
  it for six days saying exactly how to re-measure it.
