## The three things worth knowing before changing anything here

**1. The verify chain has a fifth step now, and it is not optional.**
`scripts/unix-check.sh` compiles the tree for Linux in a container. Four of the chain's five steps
run on Windows, which leaves **45 `cfg`-gated blocks across 17 files** unread — and that is not
hypothetical: `d1b3618` shipped a private associated const named across a module boundary, took
every Apple, Linux and MSRV job red, took the container harness offline with them (it builds its
binary in-image), and sat for 26 commits. `CLAUDE.md` now also states **which behaviours only the
harness can verify**, so a red harness reads as a list of unverified properties rather than a job
to re-run.

**2. The hermetic suite has a ceiling, and F17 is what it looks like.**
`cargo mutants` showed the guard's OS-essential protection could be **deleted entirely** with
every Rust test *and* all 425 harness checks green. The gap was a missing **input**, not a missing
assertion: no mock had ever reported an essential set, so `essential_names` returned empty in
every test that has ever run. There is an `Essentials` fixture in `guard.rs` now, and a nightly
`cargo mutants` job over `guard.rs`, `exit.rs`, `datalock.rs` and `transaction.rs`.

*If you run that job by hand: do not scope it with `--test suite <filter>`.* That runs the
integration target only, and it is what made the first measurement eight missed mutants out of
eleven — including `GuardScope::reconciles` in both directions, which a **lib** test asserts for
all twelve scopes.

**3. F15 is the one where the bisect pointed at the right commit for the wrong reason.**
`d1b3618` correctly taught the apt lister to read `${db:Status-Status}`, so `unpacked` and
`half-configured` parse as *not installed* — which they are. It exposed a hole rather than
creating one. A `SIGKILL` mid-`apt` wedges dpkg, so `heal`'s replay fails, and the failure branch
ended with *"the entry stays recorded as interrupted, so nothing claims this package is
installed"* — while the kill had left the package **unpacked, on disk, on `PATH`**. The registry
claimed nothing, so `uninstall` reported success and took nothing away, for ever.

The rule now: **an install Shall started is Shall's to own, whether or not recovery finishes it.**
Ownership is not a claim that the package is installed; it is a claim that Shall is answerable for
what the operation left behind. Its sibling would have made the fix inert — the registry write at
the end of `heal` was gated on `recovered || kept`, and the group-kill run is exactly the one
where every replay fails.

## Traps this round paid for, again

- **`rc=$?` after a pipe reads the pipe.** The grade doc has this as lesson 2 and I still did it —
  a container check reported `exit 0` while printing `No such file or directory`.
- **Two `cargo` processes fight over the test binary.** `LNK1104` / *"Access is denied"* removing
  `shall.exe` means a suite is still running, not that anything is broken. And a fix that lands
  mid-run makes that run's result evidence about the *old* code, which cost one wasted 14-minute
  suite here.
- **WSL path translation.** `wsl -- bash /tmp/x.sh` resolves `/tmp` against Windows; Git Bash
  rewrites `/mnt/c/...` into `C:/Program Files/Git/mnt/c/...`. Drive WSL from PowerShell and pass
  the script by its `/mnt/c` path. WSL also cold-starts between invocations and wipes `/tmp`.
- **`mutants.out/` is ignored now.** This session opened with a cargo-mutants-mutated `guard.rs`
  sitting in the working tree from an interrupted run — `preview_refusals` replaced with
  `vec![String::new()]`.
