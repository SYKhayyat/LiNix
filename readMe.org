* Introduction

LiNix is a cross‑platform, multi‑backend declarative package manager written in Rust. It is designed as a *system state engine*, treating your local machine like a production server: the state of your software must always match the defined configuration.

Unlike simple CLI wrappers or imperative scripts, LiNix is *bi‑directional*. Install a package manually from the command line, and it automatically updates your declarative configuration. Sync your configuration, and LiNix ensures your system reflects it exactly—with transactional safety, parallel execution, and cryptographic verification.

* Key Features

** Mission‑Critical Reliability

- *Transactional journaling*: every =sync= operation writes to a real‑time journal (=pending.json=). If your computer crashes or loses power mid‑sync, LiNix knows exactly where it left off.
- *Heal command*: a dedicated recovery tool that reads the transaction journal to resume and repair interrupted installations, leaving your system in a consistent state.
- *Pre‑sync atomic snapshots*: before any change, LiNix creates a timestamped JSON backup of your entire package configuration, enabling instant rollbacks of the configuration state.
- *Priority scheduling*: system‑level managers (e.g., =apt=, =dnf=) finish their work before language‑specific managers (e.g., =cargo=, =pip=) begin, preventing dependency race conditions.
- *On‑disk conflict detection*: scans your =$PATH= before installing to avoid accidentally shadowing or overwriting binaries you’ve placed outside the manager.

** Advanced Logic & Reproducibility

- *Recursive group expansion*: groups can include other groups (e.g., a =work= group that includes =dev= and =security=). LiNix resolves these with queue‑based expansion, infinite depth, and cycle detection.
- *Lockfile support*: generate a =linix.lock= with exact version strings across all backends—similar to =Cargo.lock= or =package-lock.json=. Use =linix sync --locked= to reproduce a system state down to the specific version on any machine.
- *Backend aliases*: map custom nicknames (e.g., =sys= → =pacman= on Arch, =sys= → =apt= on Ubuntu) to keep group files portable across distributions.

** Hardened Security & Safety

- *SHA256 verification*: verify GitHub binary downloads with the =@sha256= option, pinning hashes to guard against tampering.
- *Lua hooks*: programmable hooks (before/after sync, before/after install) run in a sandboxed Lua environment for safe automation.
- *Post‑install health checks*: automatically verify that a package’s binary is in =$PATH= immediately after installation using the =@verify_binary= option.

** Power‑User UX & Extensibility

- *Interactive provider selection*: when a package exists in multiple backends (e.g., =ripgrep= in =apt=, =snap=, and =cargo=), LiNix presents an interactive TUI menu to let you choose your preferred source.
- *Universal search*: a high‑performance, asynchronous search engine that queries all enabled backends in parallel and aggregates results into a single list.
- *Hostname‑specific profiles*: automatically detects your machine’s hostname and merges =host-<name>.txt= files into your sync plan, allowing one configuration directory to manage a laptop, a desktop, and a server differently.

* Supported Backends

LiNix provides mature, native implementations for the following package managers:

| Category   | Backends                                                                                      |
|------------+-----------------------------------------------------------------------------------------------|
| System     | =apt=, =dnf=, =pacman=, =apk=, =zypper=                                                         |
| Universal  | =flatpak=, =snap=, =brew=                                                                       |
| Language   | =cargo= (with =binstall= support), =npm=, =pip=, =pnpm=, =yarn=                                   |
| Tools      | =uv=, =mise=, =pipx=, =vscode=, =github=                                                         |
| Windows    | =winget=, =choco=, =scoop=                                                                      |

* Installation

** From source

#+BEGIN_SRC bash
  # Clone this repo.
  cd linix
  cargo build --release
  sudo cp target/release/linix /usr/local/bin/
#+END_SRC

* Configuration

** Main config (~/.config/linix/config.toml~)

#+BEGIN_SRC toml
enabled_backends = ["apt", "flatpak", "cargo", "github"]
github_token = "ghp_your_token_here"  # higher rate limits

[aliases]
sys = "apt"

[groups]
base-dev = ["sys:git", "sys:curl", "sys:build-essential"]
rust-stack = ["base-dev", "cargo:ripgrep@verify_binary=rg"]
#+END_SRC

** Group files (~/.config/linix/groups/local.txt~)

#+BEGIN_SRC text
rust-stack
github:neovim/neovim@sha256=a1b2c3d4...
#+END_SRC

Host‑specific files (e.g., =host-desktop.txt=) are merged automatically.

* Usage

| Command                 | Description                                                       |
|-------------------------+-------------------------------------------------------------------|
| =linix sync=            | Sync system to match group files.                                 |
| =linix sync --locked=   | Sync using exact versions from =linix.lock=.                        |
| =linix heal=            | Resume an interrupted or crashed sync session.                    |
| =linix doctor=          | Check health and availability of all backends.                    |
| =linix rollback=        | Restore group files from a previous snapshot.                     |
| =linix clean=           | Interactively remove packages not defined in the config.          |
| =linix install <pkg>=   | Install a package and save it to =local.txt=.                       |

* LiNix vs. The Competition

** vs. Metapac

While projects like Metapac provide an excellent CLI wrapper, LiNix is built for mission‑critical stability:

- *Resilience*: LiNix offers a =heal= command and transactional journals; Metapac is stateless.
- *Security*: LiNix supports native SHA256 checksums for GitHub downloads; Metapac relies on backend defaults.
- *Logic*: LiNix supports recursive group expansion (groups within groups); Metapac uses flat lists.
- *Maturity*: LiNix provides full support for =apk=, =choco=, and =pip=, which are currently on Metapac’s wishlist.

** vs. Shell Scripts

- *Speed*: LiNix executes installations in parallel where possible.
- *Safety*: atomic rollbacks and recovery commands ensure you never leave the system half‑configured.
- *Completeness*: uninstalls and cleanup are handled automatically—shell scripts almost always ignore these.

** vs. Nix / Guix

- *Familiarity*: LiNix works on top of your existing, native package managers (apt, brew, winget, etc.), avoiding a specialized filesystem or DSL.
- *Integration*: manual installations update your declarative configuration automatically, preserving the bi‑directional workflow.
