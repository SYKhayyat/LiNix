# Real GitHub release asset lists, fetched 2026-07-23, verified by hand (D2).
#
# A block is `## owner/repo tag`, then one `-> platform = expected` line per platform LiNix
# was checked on, then the release's assets exactly as the API returned them. The expectation
# is the asset `select` must choose with that platform's default format order; `none` means
# no asset is installable there and the error must say so.
#
# This file exists because `binary` is the one classification that fails quietly: a wrong
# extension guess errors, a wrong `binary` guess installs the wrong file and says nothing.
#
# Two expectations below are RECORDED, NOT ENDORSED, and both are the same finding: jq on
# linux and macos, and rclone on macos, choose the project's SOURCE tarball over a binary that
# names the exact machine. It happens because the tie-break ranks format order above
# specificity, and a detected default order is not something the user asked for. LiNix errors
# afterwards ("no executable found in the archive"), so it is loud rather than silent — but it
# is the wrong file. Changing the tie-break is a design decision and is not made here.
#
# rclone's macos case has a second cause worth keeping separate: the macos default order is
# dmg, pkg, tarball, binary and does not include zip, while rclone (and gh, and starship) ship
# their macos build as a .zip.
